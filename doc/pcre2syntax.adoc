== PCRE2 regular expression syntax summary

The full syntax and semantics of the regular expression patterns that are
supported by PCRE2 are described in the
xref:pcre2pattern.adoc[`pcre2pattern`]
documentation. This document contains a quick-reference summary of the pattern
syntax followed by the syntax of replacement strings in substitution function.
The full description of the latter is in the
xref:pcre2api.adoc[`pcre2api`]
documentation.

== Quoting

[.regex]`{backslash}__x__`:: where _x_ is non-alphanumeric, matches a literal _x_
[.regex]`+\Q...\E+`::        treat enclosed characters as literal

Note that white space inside [.regex]`+\Q...\E+` is always treated as literal, even if
const:PCRE2_EXTENDED is set, causing most other white space to be ignored. Note also
that PCRE2's handling of [.regex]`+\Q...\E+` has some differences from Perl's. See the
xref:pcre2pattern.adoc[`pcre2pattern`]
documentation for details.

== Braced items

With one exception, wherever brace characters [.regex]`+{+` and [.regex]`}` are required to enclose
data for constructions such as [.regex]`+\g{2}+` or [.regex]`+\k{name}+`, space and/or horizontal tab
characters that follow [.regex]`+{+` or precede [.regex]`}` are allowed and are ignored. In the case
of quantifiers, they may also appear before or after the comma. The exception
is [.regex]`+\u{...}+` which is not Perl-compatible and is recognized only when
const:PCRE2_EXTRA_ALT_BSUX is set. This is an ECMAScript compatibility feature, and
follows ECMAScript's behaviour.

== Escaped characters

This table applies to ASCII and Unicode environments. An unrecognized escape
sequence causes an error.

[.regex]`\a`                  :: alarm, that is, the BEL character (char:0x07)
[.regex]`\c__x__`             :: "control-__x__", where _x_ is a non-control ASCII character
[.regex]`\e`                  :: escape (char:0x1B)
[.regex]`\f`                  :: form feed (char:0x0C)
[.regex]`\n`                  :: newline (char:0x0A)
[.regex]`\r`                  :: carriage return (char:0x0D)
[.regex]`\t`                  :: tab (char:0x09)
[.regex]`\0__dd__`            :: character with octal code 0__dd__
[.regex]`{backslash}__ddd__`  :: character with octal code _ddd_, or backreference
[.regex]`\o{_ddd\..._}`       :: character with octal code _ddd\..._
[.regex]`\N{U+_hh\..._}`      :: character with Unicode code point _hh\..._ (Unicode mode only)
[.regex]`\x__hh__`            :: character with hex code _hh_
[.regex]`\x{__hh\...__}`      :: character with hex code _hh\..._

[.regex]`\N{U+_hh\..._}` is synonymous with [.regex]`\x{_hh\..._}` but is not supported in environments
that use EBCDIC code (mainly IBM mainframes). Note that [.regex]`\N` not followed by an
opening curly bracket has a different meaning (see below).

If const:PCRE2_ALT_BSUX or const:PCRE2_EXTRA_ALT_BSUX is set ("ALT_BSUX mode"), the
following are also recognized:

[.regex]`\U`           :: the character "U"
[.regex]`\u__hhhh__`   :: character with hex code _hhhh_
[.regex]`\u{_hh\..._}` :: character with hex code _hh\..._ but only for EXTRA_ALT_BSUX

When [.regex]`\x` is not followed by [.regex]`+{+`, one or two hexadecimal digits are read,
but in ALT_BSUX mode [.regex]`\x` must be followed by two hexadecimal digits to be
recognized as a hexadecimal escape; otherwise it matches a literal [.subject]`x`.
Likewise, if [.regex]`\u` (in ALT_BSUX mode) is not followed by four hexadecimal digits
or (in EXTRA_ALT_BSUX mode) a sequence of hex digits in curly brackets, it
matches a literal [.subject]`u`.

Note that [.regex]`\0__dd__` is always an octal code. The treatment of backslash followed by
a non-zero digit is complicated; for details see the section
xref:pcre2pattern.adoc#non-printing-characters[Non-printing characters]
in the
xref:pcre2pattern.adoc[`pcre2pattern`]
documentation, where details of escape processing in EBCDIC environments are
also given.

== Character types

[.regex]`.`         :: any character except newline; in dotall mode, any character whatsoever
[.regex]`\C`        :: one code unit, even in UTF mode (best avoided)
[.regex]`\d`        :: a decimal digit
[.regex]`\D`        :: a character that is not a decimal digit
[.regex]`\h`        :: a horizontal white space character
[.regex]`\H`        :: a character that is not a horizontal white space character
[.regex]`\N`        :: a character that is not a newline
[.regex]`\p{_xx_}`  :: a character with the _xx_ property
[.regex]`\P{_xx_}`  :: a character without the _xx_ property
[.regex]`\R`        :: a newline sequence
[.regex]`\s`        :: a white space character
[.regex]`\S`        :: a character that is not a white space character
[.regex]`\v`        :: a vertical white space character
[.regex]`\V`        :: a character that is not a vertical white space character
[.regex]`\w`        :: a "word" character
[.regex]`\W`        :: a "non-word" character
[.regex]`\X`        :: a Unicode extended grapheme cluster

[.regex]`\C` is dangerous because it may leave the current matching point in the middle
of a UTF-8 or UTF-16 character. The application can lock out the use of [.regex]`\C` by
setting the const:PCRE2_NEVER_BACKSLASH_C option. It is also possible to build PCRE2
with the use of [.regex]`\C` permanently disabled.

By default, [.regex]`\d`, [.regex]`\s`, and [.regex]`\w` match only ASCII characters, even in UTF-8 mode
or in the 16-bit and 32-bit libraries. However, if locale-specific matching is
happening, [.regex]`\s` and [.regex]`\w` may also match characters with code points in the range
128--255. If the const:PCRE2_UCP option is set, the behaviour of these escape
sequences is changed to use Unicode properties and they match many more
characters, but there are some option settings that can restrict individual
sequences to matching only ASCII characters.

Property descriptions in [.regex]`\p` and [.regex]`\P` are matched caselessly; hyphens,
underscores, and ASCII white space characters are ignored, in accordance with
Unicode's "loose matching" rules. For example, [.regex]`+\p{Bidi_Class=al}+` is the same
as [.regex]`+\p{ bidi class = AL }+`.

== PCRE2 special category properties for [.regex]`\p` and [.regex]`\P`

[.regex]`Xan`:: Alphanumeric: union of properties [.regex]`L` and [.regex]`N`
[.regex]`Xps`:: POSIX space: property [.regex]`Z` or tab, NL, VT, FF, CR
[.regex]`Xsp`:: Perl space: property [.regex]`Z` or tab, NL, VT, FF, CR
[.regex]`Xuc`:: Universally-named character: one that can be represented by a
Universal Character Name
[.regex]`Xwd`:: Perl word: property [.regex]`Xan` or underscore

Perl and POSIX space are now the same. Perl added VT to its space character set
at release 5.18.

== Binary properties for [.regex]`\p` and [.regex]`\P`

Unicode defines a number of binary properties, that is, properties whose only
values are true or false. You can obtain a list of those that are recognized by
[.regex]`\p` and [.regex]`\P`, along with their abbreviations, by running this command:

[source,shell]
----
pcre2test -LP
----

== Script matching with [.regex]`\p` and [.regex]`\P`

Many script names and their 4-letter abbreviations are recognized in
[.regex]`+\p{sc:...}+` or [.regex]`+\p{scx:...}+` items, or on their own with [.regex]`\p` (and also [.regex]`\P` of
course). You can obtain a list of these scripts by running this command:

[source,shell]
----
pcre2test -LS
----

== Character classes

[.regex]`+[...]+`:: Positive character class
[.regex]`+[^...]+`:: Negative character class
[.regex]`[x-y]`:: Range (can be used for hexadecimal characters)
[.regex]`{startsb}{startsb}:__xxx__:]]`:: Positive POSIX named set
[.regex]`{startsb}{startsb}:^__xxx__:]]`:: Negative POSIX named set

The recognized POSIX named sets are:

[.regex]`alnum`:: Alphanumeric
[.regex]`alpha`:: Alphabetic
[.regex]`ascii`:: 0--127
[.regex]`blank`:: Space or tab
[.regex]`cntrl`:: Control character
[.regex]`digit`:: Decimal digit
[.regex]`graph`:: Printing, excluding space
[.regex]`lower`:: Lower case letter
[.regex]`print`:: Printing, including space
[.regex]`punct`:: Printing, excluding alphanumeric
[.regex]`space`:: White space
[.regex]`upper`:: Upper case letter
[.regex]`word`:: Same as [.regex]`\w`
[.regex]`xdigit`:: Hexadecimal digit

In PCRE2, POSIX character set names recognize only ASCII characters by default,
but some of them use Unicode properties if const:PCRE2_UCP is set. You can use
[.regex]`+\Q...\E+` inside a character class.

When const:PCRE2_ALT_EXTENDED_CLASS is set, UTS#18 extended character classes may be
used, allowing nested character classes, combined using set operators.

[.regex]`[x&&[^y]]`:: UTS#18 extended character class
[.regex]`x||y`:: Set union (OR)
[.regex]`x&&y`:: Set intersection (AND)
[.regex]`+x--y+`:: Set difference (AND NOT)
[.regex]`x~~y`:: Set symmetric difference (XOR)

== Perl extended character classes

[.regex]`+(?[...])+`:: Perl extended character class
[.regex]`(?[\p{Thai} & \p{Nd}])`:: Operators; white space ignored
[.regex]`(?[(_X_ - _Y_) & _Z_])`:: Parentheses for grouping

[.regex]`(?[ [^3] & \p{Nd} ])`:: [.regex]`+[ ... ]+` is a nested ordinary class
[.regex]`(?[ [:alpha:] - [z] ])`:: POSIX set is allowed outside [.regex]`+[ ... ]+` but character literal must be enclosed
[.regex]`(?[ \d - [3] ])`:: Backslash-escaped set is allowed outside [.regex]`+[ ... ]+`
[.regex]`(?[ !\n & [:ascii:] ])`:: Backslash-escaped character is allowed outside
[.regex]`+[ ... ]+`; all other characters or ranges must be enclosed in [.regex]`+[ ... ]+`

[.regex]`x|y`, [.regex]`x+y`:: Set union (OR)
[.regex]`x&y`:: Set intersection (AND)
[.regex]`x-y`:: Set difference (AND NOT)
[.regex]`x^y`:: Set symmetric difference (XOR)
[.regex]`!x`:: Set complement (NOT)

Inside a Perl extended character class, [.regex]`+[...]+` switches mode to be interpreted
as an ordinary character class. Outside of a nested [.regex]`+[...]+`, the only items
permitted are backslash-escapes, POSIX sets, operators, and parentheses. Inside
a nested ordinary class, [.regex]`^` has its usual meaning (inverts the class when used
as the first character); outside of a nested class, [.regex]`^` is the XOR operator.

== Reported match point setting

[.regex]`\K`:: Set reported start of match

From release 10.38, [.regex]`\K` is not permitted by default in lookaround assertions,
for compatibility with Perl. However, if the const:PCRE2_EXTRA_ALLOW_LOOKAROUND_BSK
option is set, the previous behaviour is re-enabled. When this option is set,
[.regex]`\K` is honoured in positive assertions, but ignored in negative ones.

== Alternation

[.regex]`_expr_|_expr_|__expr__\...`:: Alternative expressions

== Capturing

[.regex]`+(...)+`:: Capture group
[.regex]`(?<__name__>\...)`:: Named capture group (Perl)
[.regex]`(?'_name_'\...)`:: Named capture group (Perl)
[.regex]`(?P<__name__>\...)`:: Named capture group (Python)
[.regex]`+(?:...)+`:: Non-capture group
[.regex]`+(?|...)+`:: Non-capture group; reset group numbers for capture groups
in each alternative

In non-UTF modes, names may contain underscores and ASCII letters and digits;
in UTF modes, any Unicode letters and Unicode decimal digits are permitted. In
both cases, a name must not start with a digit.

== Atomic groups

[.regex]`+(?>...)+`:: Atomic non-capture group
[.regex]`+(*atomic:...)+`:: Atomic non-capture group

== Comment

[.regex]`+(?#...)+`:: Comment (not nestable)

== Option setting

Changes of these options within a group are automatically cancelled at the end
of the group.

[.regex]`(?a)`:: All ASCII options
[.regex]`(?aD)`:: Restrict [.regex]`\d` to ASCII in UCP mode
[.regex]`(?aS)`:: Restrict [.regex]`\s` to ASCII in UCP mode
[.regex]`(?aW)`:: Restrict [.regex]`\w` to ASCII in UCP mode
[.regex]`(?aP)`:: Restrict all POSIX classes to ASCII in UCP mode
[.regex]`(?aT)`:: Restrict POSIX digit classes to ASCII in UCP mode
[.regex]`(?i)`:: Caseless
[.regex]`(?J)`:: Allow duplicate named groups
[.regex]`(?m)`:: Multiline
[.regex]`(?n)`:: No auto capture
[.regex]`(?r)`:: Restrict caseless to either ASCII or non-ASCII
[.regex]`(?s)`:: Single line (dotall)
[.regex]`(?U)`:: Default ungreedy (lazy)
[.regex]`(?x)`:: Ignore white space except in classes or [.regex]`+\Q...\E+`
[.regex]`(?xx)`:: As [.regex]`(?x)`, but also ignore space and tab in classes
[.regex]`+(?-...)+`:: Unset the given option(s)
[.regex]`(?^)`:: Unset [.regex]`imnrsx` options

[.regex]`(?aP)` implies [.regex]`(?aT)` as well, though this has no additional effect. However, it
means that [.regex]`(?-aP)` also implies [.regex]`(?-aT)` and disables all ASCII restrictions for
POSIX classes.

Unsetting [.regex]`x` or [.regex]`xx` unsets both. Several options may be set at once, and a
mixture of setting and unsetting such as [.regex]`(?i-x)` is allowed, but there may be
only one hyphen. Setting (but no unsetting) is allowed after [.regex]`(?^`, for example
[.regex]`(?^in)`. An option setting may appear at the start of a non-capture group, for
example [.regex]`+(?i:...)+`.

The following are recognized only at the very start of a pattern or after one
of the newline or [.regex]`\R` sequences or options with similar syntax. More than one
of them may appear. For the first three, d is a decimal number.

[.regex]`(*LIMIT_DEPTH=_d_)`:: Set the backtracking limit to _d_
[.regex]`(*LIMIT_HEAP=_d_)`:: Set the heap size limit to _d_ * 1024 bytes
[.regex]`(*LIMIT_MATCH=_d_)`:: Set the match limit to _d_
[.regex]`(*CASELESS_RESTRICT)`:: Set const:PCRE2_EXTRA_CASELESS_RESTRICT when matching
[.regex]`(*NOTEMPTY)`:: Set const:PCRE2_NOTEMPTY when matching
[.regex]`(*NOTEMPTY_ATSTART)`:: Set const:PCRE2_NOTEMPTY_ATSTART when matching
[.regex]`(*NO_AUTO_POSSESS)`:: No auto-possessification
(const:PCRE2_NO_AUTO_POSSESS)
[.regex]`(*NO_DOTSTAR_ANCHOR)`:: No [.regex]`+.*+` anchoring
(const:PCRE2_NO_DOTSTAR_ANCHOR)
[.regex]`(*NO_JIT)`:: Disable JIT optimization
[.regex]`(*NO_START_OPT)`:: No start-match optimization
(const:PCRE2_NO_START_OPTIMIZE)
[.regex]`(*TURKISH_CASING)`:: Set const:PCRE2_EXTRA_TURKISH_CASING when matching
[.regex]`+(*UTF)+`:: Set appropriate UTF mode for the library in use
[.regex]`+(*UCP)+`:: Set const:PCRE2_UCP (use Unicode properties for [.regex]`\d`, etc.)

Note that [.regex]`LIMIT_DEPTH`, [.regex]`LIMIT_HEAP`, and [.regex]`LIMIT_MATCH` can only reduce the value of
the limits set by the caller of func:pcre2_match() or func:pcre2_dfa_match(),
not increase them. [.regex]`LIMIT_RECURSION` is an obsolete synonym for [.regex]`LIMIT_DEPTH`. The
application can lock out the use of [.regex]`+(*UTF)+` and [.regex]`+(*UCP)+` by setting the
const:PCRE2_NEVER_UTF or const:PCRE2_NEVER_UCP options, respectively, at compile time.

== Newline convention

These are recognized only at the very start of the pattern or after option
settings with a similar syntax.

[.regex]`(*CR)`:: Carriage return only
[.regex]`(*LF)`:: Linefeed only
[.regex]`(*CRLF)`:: Carriage return followed by linefeed
[.regex]`(*ANYCRLF)`:: All three of the above
[.regex]`(*ANY)`:: Any Unicode newline sequence
[.regex]`(*NUL)`:: The NUL character (binary zero)

== What [.regex]`\R` matches

These are recognized only at the very start of the pattern or after option
setting with a similar syntax.

[.regex]`(*BSR_ANYCRLF)`:: CR, LF, or CRLF
[.regex]`(*BSR_UNICODE)`:: Any Unicode newline sequence

== Lookahead and lookbehind assertions

[.regex]`+(?=...)+`::
[.regex]`+(*pla:...)+`::
[.regex]`+(*positive_lookahead:...)+`::
Positive lookahead
[.regex]`+(?!...)+`::
[.regex]`+(*nla:...)+`::
[.regex]`+(*negative_lookahead:...)+`::
Negative lookahead
[.regex]`+(?<=...)+`::
[.regex]`+(*plb:...)+`::
[.regex]`+(*positive_lookbehind:...)+`::
Positive lookbehind
[.regex]`+(?<!...)+`::
[.regex]`+(*nlb:...)+`::
[.regex]`+(*negative_lookbehind:...)+`::
Negative lookbehind

Each top-level branch of a lookbehind must have a limit for the number of
characters it matches. If any branch can match a variable number of characters,
the maximum for each branch is limited to a value set by the caller of
func:pcre2_compile() or defaulted. The default is set when PCRE2 is built
(ultimate default 255). If every branch matches a fixed number of characters,
the limit for each branch is 65535 characters.

== Subroutine references (possibly recursive)

[.regex]`(?R)`:: Recurse whole pattern
[.regex]`(?_n_)`:: Call subroutine by absolute number
[.regex]`(?+_n_)`:: Call subroutine by relative number
[.regex]`(?-_n_)`:: Call subroutine by relative number
[.regex]`(?&__name__)`:: Call subroutine by name (Perl)
[.regex]`(?P>__name__)`:: Call subroutine by name (Python)
[.regex]`\g<__name__>`:: Call subroutine by name (Oniguruma)
[.regex]`\g'_name_'`:: Call subroutine by name (Oniguruma)
[.regex]`\g<__n__>`:: Call subroutine by absolute number (Oniguruma)
[.regex]`\g'_n_'`:: Call subroutine by absolute number (Oniguruma)
[.regex]`\g<+_n_>`:: Call subroutine by relative number (PCRE2 extension)
[.regex]`\g'+_n_'`:: Call subroutine by relative number (PCRE2 extension)
[.regex]`\g\<-__n__>`:: Call subroutine by relative number (PCRE2 extension)
[.regex]`\g'-_n_'`:: Call subroutine by relative number (PCRE2 extension)

The variants using parentheses [.regex]`+(?...)+` may also specify a list of capture groups
to return, which shall be retained in the calling subexpression if set during
the recursion (this feature is not supported by Perl).

[.regex]`(?R(_grouplist_))`::
Recurse whole pattern, returning capture groups
(PCRE2 extension)
[.regex]`(?_n_(_grouplist_))`::
[.regex]`(?+_n_(_grouplist_))`::
[.regex]`(?-_n_(_grouplist_))`::
[.regex]`(?&__name__(_grouplist_))`::
[.regex]`(?P>__name__(_grouplist_))`::
Call subroutine, returning capture groups
(PCRE2 extension)

The comma-separated list _grouplist_ uses the same syntax as
[.regex]`(*scan_substring:(_grouplist_)\...)`, and may identify groups in any of the
following ways:

[.regex]`_n_`:: Absolute reference
[.regex]`{plus}__n__`:: Relative reference
[.regex]`-_n_`:: Relative reference
[.regex]`<__name__>`:: Name
[.regex]`'_name_'`:: Name

== Conditional patterns

[.regex]`(?(_condition_)_yes-pattern_)`:: Conditional pattern without an alternative
[.regex]`(?(_condition_)_yes-pattern_|_no-pattern_)`:: Conditional pattern with an alternative

The forms for the _condition_ are:

[.regex]`(?(_n_)`:: Absolute reference condition
[.regex]`(?(+_n_)`:: Relative reference condition (PCRE2 extension)
[.regex]`(?(-_n_)`:: Relative reference condition (PCRE2 extension)
[.regex]`(?(<__name__>)`:: Named reference condition (Perl)
[.regex]`(?('_name_')`:: Named reference condition (Perl)
[.regex]`(?(_name_)`:: Named reference condition (PCRE2, deprecated)
[.regex]`+(?(R)+`:: Overall recursion condition
[.regex]`(?(R__n__)`:: Specific numbered group recursion condition
[.regex]`(?(R&__name__)`:: Specific named group recursion condition
[.regex]`(?(DEFINE)`:: Define groups for reference
[.regex]`(?(VERSION__[__>__]__=_n_{blank}__[__._m_{blank}__]__)`:: Test PCRE2 version
[.regex]`(?(_assert_)`:: Assertion condition

Note the ambiguity of [.regex]`+(?(R)+` and [.regex]`(?(R__n__)` which might be named reference
conditions or recursion tests. Such a condition is interpreted as a reference
condition if the relevant named group exists.

The parts within brackets for the VERSION conditional syntax can be ommited.
The fractional part of the version number defaults to 0 in that case.

== Backtracking control

All backtracking control verbs may be in the form [.regex]`(*VERB:__NAME__)`. For [.regex]`+(*MARK)+` the
name is mandatory, for the others it is optional. [.regex]`+(*SKIP)+` changes its behaviour
if [.regex]`:__NAME__` is present. The others just set a name for passing back to the caller,
but this is not a name that [.regex]`+(*SKIP)+` can see. The following act immediately they
are reached:

[.regex]`(*ACCEPT)`:: Force successful match
[.regex]`(*FAIL)`:: Force backtrack; synonym [.regex]`(*F)`
[.regex]`(*MARK:__NAME__)`:: Set name to be passed back; synonym [.regex]`(*:__NAME__)`

The following act only when a subsequent match failure causes a backtrack to
reach them. They all force a match failure, but they differ in what happens
afterwards. Those that advance the start-of-match point do so only if the
pattern is not anchored.

[.regex]`(*COMMIT)`:: Overall failure, no advance of starting point
[.regex]`(*PRUNE)`:: Advance to next starting character
[.regex]`+(*SKIP)+`:: Advance to current matching position
[.regex]`(*SKIP:__NAME__)`:: Advance to position corresponding to an earlier
[.regex]`(*MARK:__NAME__)`; if not found, the [.regex]`+(*SKIP)+` is ignored
[.regex]`(*THEN)`:: Local failure, backtrack to next alternation

The effect of one of these verbs in a group called as a subroutine is confined
to the subroutine call.

== Callouts

[.regex]`(?C)`:: Callout (assumed number 0)
[.regex]`(?C__n__)`:: Callout with numerical data _n_
[.regex]`(?C"__text__")`:: Callout with string data

The allowed string delimiters are [.regex]`'`, [.regex]`"`, [.regex]`^`,
[.regex]`%`, [.regex]`#`, and [.regex]`$` (which are the same for the start
and the end), and the starting delimiter [.regex]`+{+` matched with the ending
delimiter [.regex]`}`. To encode the ending delimiter within the string, double it.

== Replacement strings

If the const:PCRE2_SUBSTITUTE_LITERAL option is set, a replacement string for
func:pcre2_substitute() is not interpreted. Otherwise, by default, the only
special character is the dollar character in one of the following forms:

[.repl]`$$`:: Insert a dollar character
[.repl]`$_n_` or [.repl]`${_n_}`:: Insert the contents of group _n_
[.repl]`$<__name__>`:: Insert the contents of named group
[.repl]`$0` or [.repl]`$&`:: Insert the entire matched substring
[.repl]`$``:: Insert the substring that precedes the match
[.repl]`$'`:: Insert the substring that follows the match
[.repl]`$_`:: Insert the entire input string
[.repl]`$+`:: Insert the highest-numbered capture group which matched
[.repl]`$*MARK` or [.repl]`${*MARK}`:: Insert a control verb name

For [.repl]`${_n_}`, _n_ can be a name or a number. If const:PCRE2_SUBSTITUTE_EXTENDED is set,
there is additional interpretation:

. Backslash is an escape character, and the forms described in "ESCAPED
CHARACTERS" above are recognized. Also:

+
[.repl]`+\Q...\E+`:: Suppress interpretation
[.repl]`\l`:: Force the next character to lower case
[.repl]`\u`:: Force the next character to upper case
[.repl]`\L`:: Force subsequent characters to lower case
[.repl]`\U`:: Force subsequent characters to upper case
[.repl]`\u\L`:: Force next character to upper case, then all lower
[.repl]`\l\U`:: Force next character to lower case, then all upper
[.repl]`\E`:: End [.repl]`\L` or [.repl]`\U` case forcing
[.repl]`\b`:: Backspace character (note: as in character class in pattern)
[.repl]`\v`:: Vertical tab character (note: not the same as in a pattern)

. The Python form [.repl]`\g<__n__>`, where the angle brackets are part of the syntax and
_n_ is either a group name or a number, is recognized as an alternative way
of inserting the contents of a group, for example [.repl]`\g<3>`.

. Capture substitution supports the following additional forms:

+
[.repl]`${_n_:-__string__}`:: Default for unset group
[.repl]`${_n_:+__string1__:__string2__}`:: Values for set/unset group

+
The substitution strings themselves are expanded. Backslash can be used to
escape colons and closing curly brackets.
